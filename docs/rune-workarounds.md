# Working around Rune

Rune is pre-release and doesn't take pull requests, so Dupin works around what it hits. Rune is pinned to a `dev` rev in `Cargo.toml` (`dev` is never rewritten), and every crate Rune's own workspace patches is patched at the same rev. Renovate proposes a newer rev each week, and autofix.ci refreshes `Cargo.lock` and Rune's hash in `nix/cargo-vendor.nix` on that pull request (see [Rune updates](./development.md#rune-updates)). Before merging a bump, check each item below again, and add a `[patch.crates-io]` entry for any crate Rune's workspace newly patches.

- **Two `tiny-skia-path 0.11.4` packages.** Rune vendors a patched copy as a path dependency while `resvg` keeps the published one. nixpkgs' `importCargoLock` can't vendor both, so `nix/cargo-vendor.nix` uses crane, which vendors each source into its own directory.
- **Vendored crates keep `Cargo.toml.orig`.** Rune's `vendor/` copies published crates whole, and `cargo package --list`, which crane lists a Git crate's files with, rejects that file name, so `nix/cargo-vendor.nix` deletes it from the checkout.
- **Rune patches `naga` 30.0.1.** A patch applies only to a version every requirement accepts, so Dupin's own `naga` requirement stays at 30.0.1 until Rune moves its patch.
- **Hotkey conflicts with macOS's own shortcuts register successfully.** Rune names Spotlight as a chord's owner only after a `Conflict`, and Carbon reports none for it while the shortcut is on, so Dupin asks `shortcut_owner` before registering.
- **Without `embedded-fonts`, text goes through CoreText's fallback.** Rune treats only the fonts an app hands it as covering text, and a fallback lookup takes about a second cold, even for characters the system font has. Dupin builds Rune without its embedded Inter and hands it San Francisco's file instead (`dupin_mac::font::system_ui_font`), with the family name Rune reads from it (`FAMILIES` in `crates/dupin/src/main.rs`).
- **Headless renders don't follow `fit_content_height`.** `--snap` renders at the window's initial size, so `scripts/render.nu` reads the panel's height from `--tree` first.
- **The headless clock outruns real providers.** Results come from Spotlight and the file system in real time, so headless renders pass `--realtime`, which `--help` lists but Rune's README doesn't.
- **A window that fits its content keeps its top edge.** Rune resizes it from the top, with no way to keep another edge, so `position = "bottom"` swaps the panel's class for a subclass whose `setFrame:display:` keeps the bottom edge where the panel was placed (`dupin_mac::window::pin_bottom_edge`). Rune also lays the content out from the top while the frame moves on its spring, so the panel turns its motion off in that position (`Cx::reduced_motion`), and the frame and layout land together.
